# Doctor UAT Readiness Report

Scope of this pass: fix the doctor's confirmed UX defects, the Save & Next dead-end, and the mobile history-sequencing gap, using existing infrastructure wherever it already existed — without touching the rubric engine, sync architecture, or the six clinically-gated AI capabilities. Implemented in six small batches, each verified independently (`tsc`, targeted tests, fix, continue) before moving to the next.

### Additional fixes made in passing (small, explicitly cited, low-risk)
- Gender no longer silently defaults to "Male" (`WORLD_CLASS_CLINIC_UI_GUIDELINES.md` §6: a required field with no natural default must not pre-select a value indistinguishable from an intentional choice). Now requires an explicit choice; existing tests that didn't set gender were updated to do so (a legitimate test-setup gap the change surfaced, not an implementation bug — documented in the same commit).
- Desktop-authored keyboard hint ("↑↓ navigate, Enter to open") no longer shows in the mobile patient-search placeholder.
- The disabled "Repeat Last Selection" button now has an inline caption ("Available when last visit improved") instead of being silently greyed out.

## 2. Remaining known issues (not fixed in this pass — disclosed, not hidden)

- **ConsultationPage.tsx's own Quick-Mode-desktop dosage picker** (a plain `<select>` at the `!isMobile` branch inside Quick Mode, separate from `PrescriptionEditor.tsx`) still has no "Other" option and is still a native `<select>`. Lower priority since it's desktop-only and Quick Mode is the mobile-first surface, but it is a literal sibling of the exact defect fixed elsewhere — worth a follow-up pass.
- **CLINIC_WORKFLOW_OPTIMIZATION.md's full redesign** (sticky always-visible header/save bar, one-tap "decision row" showing what Repeat would do, per-field favorites for potency/frequency, retiring the "More…" preset row into "recent" chips) was deliberately **not** implemented — the task scope was to fix the specific reported defects and sequencing problem, not redesign the workflow. That document's broader recommendations remain a legitimate, separately-scoped follow-up project.
- **Edit/Delete icon equal-visual-weight** on the patient list (`WORLD_CLASS_CLINIC_UI_GUIDELINES.md` §7's destructive-action de-emphasis rule) was not addressed — cosmetic, lower priority, out of this pass's scope.
- **Real-device testing was not performed.** All verification in this pass ran against `fake-indexeddb` (Vitest), a headless Playwright browser, and one live dev-server DOM-measurement check via JavaScript execution (no screenshot capability was available in this session's browser tooling) — not a real Android phone in a real clinic. This is a pre-existing, disclosed gap (`docs/handover/05_TECHNICAL_DEBT_REGISTER.md` DEBT-12), not something this pass could close.
- **No doctor has used this exact build yet.** That is the explicit purpose of the UAT this report is clearing the build for — it is not itself evidence of real-world fitness.

This report does not claim real Google Drive validation has passed; it claims only that the existing, already-passing sync test suite continues to pass and that no sync code was touched.

## 7. Clinical safety considerations

- **No clinical recommendation logic was changed.** `decisionRules.canRepeat`, `getFollowUpActions`, remedy-scoring logic (`remedyEngine.ts`), and rubric suggestion/approval logic are byte-for-byte untouched.
- **No clinically-gated AI capability was activated, deleted, or silently wired into prescribing**, per the explicit stop condition — confirmed by `git status` showing zero changes to any of the nine gated files/components listed in the task.
- **The duplicate-patient warning is non-blocking by design** specifically because a hard block risked preventing legitimate distinct patients (family members sharing a phone/name) from being registered — this was a deliberate, reviewed trade-off, not an oversight, and is covered by an automated test proving genuinely different patients are never blocked.
- **The gender-default removal is the one behavior change with the most "clinical data quality" framing** (per the UI guidelines, an unreviewed default risks silently mis-recording a patient's gender). It requires one additional tap per new patient registration — a deliberate, disclosed trade-off between speed and data accuracy, not a defect.
- **Rubric Intelligence Engine Phase 1 is fully preserved**: suggestion generation, pending state, doctor approval/rejection, audit logging, history, search, analytics, and backup/restore were not touched in this pass, and no AI-generated rubric can automatically alter clinical state (unchanged).

## 8. Recommended UAT scenarios

1. **Duplicate patient**: register a patient, then attempt to register a second one with the same phone (different formatting) and the same name+age with a blank phone. Confirm the warning appears with correct identifying detail, and that both "Open existing" and "Continue creating new" behave as expected. Also register two genuinely different family members sharing a phone number and confirm no warning blocks it inappropriately.
2. **Custom frequency**: in a consultation, add a medicine and set its frequency to something not in the presets (e.g. "alternate days", "SOS after food"). Confirm it saves, prints, and displays correctly on the prescription.
3. **Remedy selection speed**: add 2+ medicines in one consultation via the remedy suggestion dropdown; confirm the dropdown never stays open over the form.
4. **Mobile patient header**: on a real Android phone (not just the emulated viewports tested here), select a patient with a long name and multiple info pills; confirm "Start Consultation" is fully visible and tappable, and the three stat cards are legible.
5. **Save & Next, full queue**: with 2+ patients waiting, run a full consultation for the first, tap Save & Next, and confirm the app lands directly on the second patient's consultation — not on Today.
6. **Save & Next, empty queue**: with no other patient waiting, confirm a normal save still returns to Today as before.
7. **Patient history on mobile**: open a returning patient's consultation on a phone and confirm the last-visit summary is visible before typing today's complaint.
8. **Full backup/restore and sync round-trip** (real device, real Google account if available): this pass did not execute a live Google Drive validation — a real doctor UAT session is the first opportunity to do so meaningfully.
